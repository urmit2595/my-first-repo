# Requests between modules

Append one line per request: `- [from → to] request`. The orchestrator relays and marks them done.

- [geometry → engine] SpireGeom notes: `w.walkables` lists every walk candidate, including covered tiles and edge-on stairs, so filter on `standable`. Ids use REFERENCE cells and never change when a group moves, so a riding Wick keeps his tile id. `w.bounds()` returns world-space CORNERS (all blocks of all values lie inside [min,max]). `SpireGeom.screen(v)` returns [sx, sy] with sy UP-positive (the formula in 4.1). Extra helpers: `w.toWorld(gid, refPoint, v?)`, `w.cellToWorld`, `w.dirToWorld`, `w.handlePos(gid, v?)` (world centre of the handle's face), `w.refOccupied(gid,x,y,z)` (for Blocks ctx.occupied), `w.edges()`, `w.solids()`, `w.resolve(alias)`, `w.label(id)`, `w.startId`, `w.goalId`, `w.plates` (resolved), `w.glimmers` (ids), `w.reset()`, `w.setValues({..})`, `w.screenToPQ(sx,sy)`. `setValue` accepts any multiple of 90 (rotor) or any integer (slider), not only the allowed values.
- [geometry → engine] The solver's walk model, which the engine must match: a walk follows `w.path()` and stops at the first ACTIVE plate after the start tile (a used once-plate is inactive). Walking off a plate does not trigger it. The goal counts only when a walk ENDS on it. A plate on an x/z rotor while Wick stands on that rotor is locked and does nothing. Tell me if the engine differs.
- [geometry → materials] A cube tile is standable only while its REFERENCE top still faces +y (an x/z rotor at 90/180 makes it unwalkable), so put pavers only on the reference +y face of walk!==false cubes, plus the ramps of stairs.
- [geometry → orchestrator] Section 4.5 rule: I found no case where it gives a visibly wrong answer (seed levels checked by eye in design/qa/geom/*.png). Two clarifications I applied: (1) a tile also needs its rotated up to be +y (see the materials note above); (2) an invalid rotor pivot is a load ERROR, not only a solver warning, because cells would not be integers.
- [geometry → level designer] Tools: `node tools/solve.js --all`; `node tools/solve.js --level ID --svg design/qa/geom/ID.svg [--states solution|start|all|"g=90;g=180"] [--graph] [--samples]`; then `node tools/svgshot.js design/qa/geom/ID.svg` gives the PNG.
